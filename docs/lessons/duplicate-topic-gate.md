# 同一個關鍵字被自家 5 個 URL 瓜分：重複選題與轉址殘骸的雙重競食

> 摘要：GSC 90 天比對發現 `髖關節痛` 被自家 5 個 URL 瓜分、全卡 pos 76-83，健康長尾 1,022 曝光 0 點擊 ｜ 範圍：SEO/自動化 ｜ 狀態：gate 已上線、內容整併待處理 ｜ 日期：2026-07-28

## 問題（症狀）

2026-07-28 拉 GSC 90 天（2026-04-26 ~ 07-25，284 clicks / 14,789 impressions）與站上內容做比對，三件事同時浮出來：

1. **健康長尾有大量需求，但全卡在第 8 頁。** `髖關節痛` 168 曝光 pos 79.8、`中醫美顏針` 147 曝光 pos 80.7、`prp 玻尿酸 比較` 45 曝光 pos 60.9。整個叢集約 1,022 曝光、**0 點擊**。28 天資料顯示需求持續（中醫美顏針 128 曝光），不是舊聞衰退。

2. **同一個字被自家多個 URL 瓜分。** `髖關節痛` 一個字有 5 個自家 URL 同時排：

   ```
   i76 pos80.7  /articles/髖關節疼痛看哪一科…/     ← 舊網址轉址頁
   i50 pos83.2  /articles/post-426/                ← 舊網址轉址頁
   i47 pos78.1  /articles/髖關節痛有哪些症狀…/     ← 舊網址轉址頁
   i4  pos74.8  /articles/hip-pain-symptoms-causes-treatment/   ← 正本
   i3  pos76    /articles/appi-news-91/
   ```

   而且 `appi-news-91`（2026-07-13）與 `hip-pain-which-specialist`（2026-04-23）是**兩篇真的在講同一題**的獨立文章（都是「髖關節痛看哪一科」）；`appi-news-82` 與 `desk-worker-neck-pain-habits` 更是 **100% 字字相同的標題**。

3. **轉址殘骸仍在吃曝光。** 全站 131 個舊網址轉址頁持有 **2,208 曝光（佔全站 15%）、40 點擊**，部分還排在 pos 5-8——也就是說 Google 寧可排「Redirecting to…」的空殼頁，也沒排正本。

## 原因（根因）

**根因一：去重機制的涵蓋範圍不對。**
`scripts/topic-ledger.mjs` 的比對窗是 **14 天**，而且只記「推薦過的候選題」、只有 `tech-radar` 會用。但實際重複來自它蓋不到的兩個破口：

- **時間跨度**——髖關節那兩篇相隔 81 天發佈，14 天窗永遠抓不到。
- **產線**——健康類走 `/admin`、newsroom 互動、`article-write`，完全不經過 tech-radar 的帳本。

換句話說，去重下在「選題端、且只有一條產線」，但重複是在「寫入端、跨所有產線」發生的。

**根因二：meta-refresh 轉址的權重傳遞被高估了。**
`astro.config.mjs` 的註解寫：「爬蟲與 LLM 皆會跟隨、**權重幾乎全傳遞**」。GitHub Pages 是純靜態、發不了真 301，所以 Astro 為 249 筆 `src/redirects.json` 各產一頁 meta-refresh + `rel=canonical` 的轉址頁。

GSC 資料否證了這個假設：三個月後仍有 131 個殘骸頁在排名、持有 15% 的站台曝光，且**排得比正本前面**。這些頁同時帶 `noindex` 與 `canonical`——這組訊號本身是矛盾的（noindex 說「丟掉這頁」，canonical 說「這頁等同那頁」），Google 對此的處理不保證是我們要的方向，最壞情況會把 noindex 一併傳遞到 canonical 目標。

## 解法（怎麼修 + 現在怎麼維持）

**已上線：選題重複 gate（`scripts/check-duplicate-topic.mjs`）**

下在**寫入端**（`newsroom-write.mjs`，配圖 gate 之後），涵蓋所有產線。判準邏輯在 `scripts/lib/topic-similarity.mjs`，以全站 480 篇實跑校準：

- **ERROR（exit 1，擋發佈）**：標題 bigram 相似度 ≥ 45%＝幾乎同一篇。
- **WARN（只印，不擋）**：主題詞重疊 ≥ 4 字且標籤重疊 ≥ 30%。

**為什麼同主題只警告不硬擋**：新聞站正當地會追蹤同一條線。校準時 9 組命中裡有 4 組是 `離岸風電` R3.3 續報與 `SK 海力士` 後續報導——硬擋會誤傷正常的新聞追蹤。這沿用 `check-content.mjs` 既有的兩級哲學。

**校準時踩到的坑**：一開始只用「標題相似度 + 標籤重疊」，結果誤報全部來自中文標題套語——「百菇湯**功效有哪些**」與「蔓越莓**功效有哪些**」共享 5 字、標籤 100% 重疊，但講的是兩種食材。加上 `GENERIC_RUNS` 套語表（功效／有哪些／一次看懂／保健功效…）後誤報歸零（11 組 → 9 組，其中 2 組正是這類）。**單看標籤重疊完全不能當判準**：健康文泛標籤重疊率極高。

**已上線：seo-ops 目標字改用實證字**

`/root/seo-ops/sites/appi.news.json` 的 `targetQueries.pinned` 原本是 `appi.news / 新聞聚合 / 即時新聞 / 亞太 新聞 / 專業觀點 評論`——實測 **5 個裡 4 個 90 天 0 曝光**，每日 reflect/brain 等於對著沒有需求的字做修正。已改為品牌 + 健康長尾 + 能源水利政策三組實證字。

**刻意不釘高溫警報字**：`黃色警報 - 高溫`、`極端高溫警報` 等字合計 864 曝光、pos 6.6、**0 點擊**。這些字面就是氣象警特報的燈號標籤，Google 直接用天氣面板回答，排第 7 也拿不到點擊。追蹤它會讓反思層去優化一個結構上拿不到流量的字。**高曝光不等於高機會。**

## 怎麼避免重犯 / 相關

- **去重要下在寫入端，不是選題端**。選題端的帳本只覆蓋一條產線、一個短時間窗；只要有第二條產線或跨月重複，它就漏。
- **「轉址已處理」不等於「權重已傳遞」**——要用 GSC 的 page 維度實際查殘骸還吃多少曝光，不要相信註解裡的假設。本站現況：131 頁殘骸吃 15% 曝光。
- **判重複不能只看標籤**，中文標題套語會製造大量假相似；要區分「主題詞」與「鷹架詞」。
- **釘目標關鍵字前先用 GSC 驗有沒有曝光**，否則反思層會對著幻覺優化整整數月。
