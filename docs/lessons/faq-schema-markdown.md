# FAQPage 結構化資料只認 HTML 標題，新文章寫的是 markdown，全站 92 篇的常見問題段白寫

> 摘要：`extractFaq()` 吃的是原始 body，三條抽取規則卻全部只比對 HTML 標題；WordPress 舊文內嵌 `<h2>常見問題</h2>` 所以有 FAQPage，新寫文章的 `### 常見問題` 一個都抽不到 ｜ 範圍：SEO / 結構化資料 ｜ 狀態：已解決 ｜ 日期：2026-08-04

## 問題（症狀）

三篇當日新上線的醫師署名文（`appi-news-496/497/498`）都寫了完整的「常見問題」段、每篇 5 題 Q&A，線上頁面卻沒有輸出 `FAQPage` 結構化資料——JSON-LD 只有 `OpinionNewsArticle`、`BreadcrumbList`、`WebPage` 等，`FAQPage` 完全不在。

盤點後發現不是這三篇的問題：全站 662 篇裡，**只有 122 篇抽得到 FAQ**，另外 **90 篇寫了常見問題段卻一則都抽不到**。等於作者花力氣寫的 Q&A 拿不到 FAQ 複合式搜尋結果，也少掉 AI 答題引擎最好嚼的那一塊結構化內容。

症狀特別難發現的原因：**有些文章是好的**。抽查會抽到 `thyroid-tsh-subclinical` 這種正常輸出 FAQPage 的頁面，看起來功能是通的。

## 原因（根因）

`src/utils/faq.ts` 的三條規則全部寫成 HTML 比對：

```ts
const start = /<(h[234])>[^<]*(?:常見問題|FAQ|...)<\/\1>/i.exec(body);   // 區段起點
const qa    = /<(h[234])>([\s\S]*?)<\/\1>\s*([\s\S]*?)(?=<h[234]>|$)/g;  // 標題式 Q&A
const qre   = /<(h[234])>\s*(Q\s*\d+[\s\S]*?)<\/\1>.../gi;               // 全文 Q1/Q2
```

但呼叫端傳的是 `article.body`，也就是**還沒渲染的原始 markdown**（`src/pages/articles/[slug].astro`）。於是：

- **WordPress 搬過來的舊文**：正文本身就內嵌 HTML（`<h2>常見問題</h2>`、`<p><strong>Q</strong><br>A</p>`）→ 比對得到 → 有 FAQPage。**這就是讓 bug 看起來不存在的那批。**
- **之後所有新寫的文章**：一律純 markdown（`### 常見問題` + `### Q1: …`）→ **區段起點就比對不到，三條規則同時失效** → 靜默回傳空陣列 → `if (faq.length > 0)` 直接跳過，不報錯、不留痕跡。

單元測試沒抓到，是因為 `faq.test.ts` 五個案例的輸入**全部是 HTML 字串**——測的是抽取邏輯本身，沒有測「真實文章長什麼樣」。測試與正式資料的形態脫節，就是這個 bug 活下來的原因。

## 解法（怎麼修 + 現在怎麼維持）

在 `extractFaq()` 進入點加一層 `normalizeMarkdown()`，把 markdown 正規化成三條規則本來就認得的形狀，**規則本體不動**（只維護一套 HTML 版邏輯）：

1. 先移除圍欄程式碼，避免裡面的 `#` 註解被當成標題；
2. ATX 標題 `^#{2,4} 文字` → `<h3>文字</h3>`（抽取器對 h2–h4 一視同仁，只需要標題邊界）；
3. 獨立粗體行 + 其後第一個段落 → `<p><strong>問題</strong><br>答案</p>`（日更文章的另一種寫法）。

另外 `stripHtml()` 補上 markdown 殘留清理（圖片丟掉、連結只留文字、粗體/行內程式碼只留內容），否則 schema 的答案文字會夾帶 `[文字](網址)`、`**` 這些原始語法；`clean()` 補上去掉純數字編號開頭（`1.吃成藥可以配咖啡嗎？`），但要求編號後接 `.`／`、`／`：` 才砍，免得誤傷「1 歲寶寶…」這類正常問句。

**驗收（全站 662 篇跑新舊兩版對比）**：

| | 有 FAQ 的文章 | Q&A 則數 |
|---|---|---|
| 舊版 | 122 篇 | 541 則 |
| 新版 | **212 篇** | **958 則** |
| 倒退 | **0 篇** | — |

「倒退 0 篇」是這次改動的關鍵驗收項：確認新增 markdown 支援沒有讓任何一篇原本抽得到的文章變少。

## 怎麼避免重犯 / 相關

- **抽取器吃原始 body，就要用原始 body 的形態寫測試。** 這次補的四個測試案例全部是真實文章複製出來的 markdown 形態（`### Q1:` 標題式、`**問題**` 粗體式、markdown 標題 + HTML 段落混合、含連結與粗體的答案），不是手寫的乾淨 HTML。以後新增抽取規則，測試輸入一律從 `src/content/articles/` 取樣。
- **「靜默回傳空值」的功能要有全站盤點，不能靠抽查。** 這個 bug 不會讓任何東西壞掉、不會報錯、不會擋 build，只是少了一段 JSON-LD；抽查又剛好會抽到舊 WordPress 文那批正常的。判斷這類功能是否健康，要跑全站掃描比對數量，別看單頁。
- **同類風險**：任何吃 `article.body` 的工具（`src/utils/llms.ts`、摘要抽取、目錄產生…）都有同一個「HTML 舊文 vs markdown 新文」的雙形態問題，改動時先確認吃的是哪一種。
