# 存量批次回填的六個坑（內鏈、常見問題、主題中樞）

2026-08-07 一天內把三批存量工作機械化跑完：補內鏈 490 篇、補常見問題 475 篇、開 7 個主題中樞。
過程踩到的坑幾乎都不在「跑不跑得動」，而在**判準與現實對不上**，且六個都會在下一次批次作業重演。

## 一、lint 的判準比現實窄，工作清單就會騙人

**問題**：`growth-lint` 一連四個判準都比實際狀況窄，導致盤點數字全錯——

| 判準 | 錯在哪 | 影響 |
|---|---|---|
| G5 FAQ | 只認 markdown `## 常見問題`，但 `src/utils/faq.ts` markdown/HTML/`Q1` 三種都吃 | 152 篇「有 FAQ」被報成沒有 |
| G2 主題 | `get()` 在第一個引號截斷，認不得 YAML 行內陣列 `topics: ["x"]` | 補了主題仍被報成沒補 |
| G1 內鏈 | 只認 markdown 連結，整段是 `<p>` 的文章只能用 `<a href>` | 42 篇被誤判成零內鏈 |
| G1-404 | 同時收檔名與 frontmatter `slug`，但有 `slug` 時檔名不產頁 | 連到 `/articles/wp-299/` 過得了 lint 卻擋 `check:links` |

**原因**：這些判準是「照著印象中的寫法」寫的 regex，而不是照著**真正決定結果的那份程式**（渲染端、
`faq.ts`、`articleSlug()`）。判準與真實來源各寫一份，就一定會漂開。

**解法**：判準抽成共用模組（`scripts/lib/faq-detect.mjs`），並補**跨兩支比對的測試**——
`faq-detect.test.mjs` 直接跑真實存量，斷言「凡是 `extractFaq` 抽得出來的，偵測器一律要回 true」。

**怎麼避免重犯**：任何 lint／盤點工具，判準只要和渲染端重複，就要嘛共用同一支模組，
要嘛加一條「兩邊結果必須一致」的測試。**盤點數字被引用來排工作，錯的數字比沒有數字更貴。**

## 二、「同分類、同標籤」不等於「同一件事」

**問題**：補內鏈的相關度第一版直接沿用站上「延伸閱讀」的權重（同 topic ×3 ＞ 同 column +3 ＞
同分類 +2 ＞ 共同 tag +1），dry-run 連出「擦傷 → 經痛」「冷氣 → 數位銀行」。

**原因**：分類與標籤只證明「在同一個台」。既有的延伸閱讀模組能用，是因為它只需要「不離題太遠」，
而**內文插入的連結需要真的扣得上題目**，標準完全不同。

**第二版也錯**：改用標題 2-gram 重疊，仍連出同樣的東西——因為本站標題滿是模板句型
（「一次看懂」「這些警訊要立刻就醫」「調高多少」），模板詞被當成題目相關。

**解法**：TF-IDF 餘弦（標題加權 ×3 ＋ 內文前 2500 字），idf 會自動把模板詞壓到接近 0。
同分類門檻 0.05、跨分類 0.075；找不到近親的一次性新聞走第二層放寬（同子分類 0.03）；
再找不到就**留白不硬連**。

**怎麼避免重犯**：判斷「兩篇是不是同一題」不要用 metadata，用內文。metadata 只適合當加分項。

## 三、批次改檔要「只新增獨立行」，不能塞進既有句子

**問題**：手工把連結插進既有段落後，`check-content` 擋下整條 build，理由是那句話有
「不是 X，而是 Y」——但那是文章原本就有、早就上線的句子。

**原因**：`check-content` 的掃描粒度是**新增的內容**（見 `ai-tone-gate.md`）。把連結塞進既有行，
那整行在 diff 裡就是新增，於是存量舊句被拿去過硬 gate。

**解法**：所有機械回填一律**只插入新的獨立區塊**，絕不修改既有行。

**怎麼避免重犯**：任何「批次改存量正文」的工具，先問一句：我的改法會不會讓舊句子重新過 gate？

## 四、機器產生的內容會撞上內容 gate，而且撞法不直覺

**問題**：FAQ 生成第一輪 25 篇被擋，理由是「模糊引用（無出處）」；第二輪 4 篇被擋，
理由是「拔高套語（不可或缺）」。

**原因**：我在 prompt 禁止答案放連結（避免造假來源），模型就改用「研究顯示」「業界普遍認為」
這種免出處講法——正好是模糊引用的定義。**一條限制會把模型推向另一條違規**。

**解法**：把這些措辭一併列入 prompt 禁令與寫入前驗證，並給替代寫法
（不要寫「研究顯示每小時起身有幫助」，改寫成「每小時起身可以打斷靜態負荷」）。
踩到的檔案**整篇還原重生**，不留半套。

**怎麼避免重犯**：生成類批次要在寫入前跑一次和 build gate 同源的驗證，
不要等 `pnpm build` 才發現；而且要預期「禁止 A 會長出 B」。

## 五、自動產生的 id 不可以有「編碼備案」

**問題**：主題中樞雷達在標籤不在對照表時，退回用字元編碼產生 id，實際產出
`topic-k34gad`、`topic-1t21w2p2v2t3238` 這種網址，得手動改名並回填 58 篇文章的引用。

**原因**：備案機制的設計動機是「不要中斷流程」，但 id 會直接進網址 `/topics/<id>/`，
**上線後改就是壞連結**，屬於不可逆輸出。不可逆的東西不該有 fallback。

**解法**：對照表沒收錄就**放棄本次並印出要補哪一列**，不產生任何 id。

**怎麼避免重犯**：自動化產生「進網址、進資料庫鍵、進外部系統」的識別碼時，
寧可停下來要人補設定，也不要自動編一個。

## 六、地理標籤要當「面向」排除，內聚度分不開它

**問題**：主題中樞雷達第一次跑迴圈只開出 1 個就停住。

**原因**：內聚度門檻設 0.08 時，「急救常識」（真主題，0.061）和「台北市」（地理標籤，0.058）
落在同一區間，門檻放寬會一起放進來、收緊會一起擋掉。**光靠內聚度分不開主題與面向。**

**解法**：把縣市／國別／頻道級標籤列成 `FACET_TAGS` 永久排除，排除後才敢把內聚門檻降到 0.045，
讓「能源政策」「淨零轉型」這類範圍較寬但確實成立的主題過關。

**怎麼避免重犯**：分群前先問「這個標籤描述的是**題目**還是**發生在哪／屬於哪一台**」。
面向不是主題，不該進候選。
