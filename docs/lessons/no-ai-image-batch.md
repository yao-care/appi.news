# 禁用 AI 生圖之後才會冒出來的三個坑

**摘要**：站長要求某批文章「不准用 OpenAI 生圖，只能用既有圖或圖庫」。
把生圖關掉之後，三個原本被生圖掩蓋的問題同時浮出來：封面與內文撞圖、無法事後驗證哪張是生成的、
以及平行批次時模型各自跑 build 互相搶 `dist/`。

日期：2026-08-06　相關：[`image-realism-system.md`](./image-realism-system.md)

---

## 問題

原本 `get-image.mjs` 的行為是「圖庫優先，全淘汰才 AI 生成」——生圖是安全網。
站長要求整批文章完全不准生圖時，光在 prompt 裡寫「不要生圖」是不夠的（模型會忽略），
而且關掉之後才發現一連串連鎖問題。

## 原因與解法

### 坑一：prompt 不是保證，要有機械開關

模型可能忽略指示，尤其在圖庫搜不到、它「想把文章寫完」的時候。

**解法**：`NO_AI_IMAGE=1` 環境變數，在 `generate()` 與 `generatePerson()` 兩個進入點直接 `throw`
（含 `--generate` 強制生圖路徑）。刻意**硬失敗而非靜默改用圖庫**——讓呼叫端看到錯誤、
換一組 query 再試，而不是拿到一張沒人要的圖。同時把 `buildDraftPrompt` 的配圖指示改寫成
「站內既有圖重用 → 圖庫 → 換 query 重搜」，讓模型一開始就走對路徑，而不是撞牆才轉向。

### 坑二：禁生圖之後，封面與內文必然開始撞圖

實測 16 篇有 7 篇卡在配圖 gate，全是「封面與內文圖重複（距離 0）」。兩個成因：

1. **模型把封面圖又插進正文**（`<img src="/covers/<slug>.webp">`）。版面本來就會顯示封面，
   這張是多餘的，但配圖 gate 會判定重複。
2. **同一組 query 圖庫會回同一張照片**。生圖時代每次生成都不同，所以這個問題被掩蓋了。

**解法**：prompt 明確要求**封面的 `--query` 必須與每一張內文圖都明顯不同**，並提醒取完確認檔案不同。
既有稿的修法是把正文裡引用封面路徑的那張圖刪掉（markdown 與 `<img>` 兩種寫法都要處理）。

### 坑三：事後無法驗證哪張圖是生成的

`sharp` 會剝掉所有 metadata（EXIF/ICC/IPTC/XMP 全無），生成圖與圖庫圖都是 webp、
常見長寬比又都是 3:2，**看檔案分不出來**。唯一線索是圖庫圖有 `credit`（封面會寫進 `coverImageCredit`），
但內文圖的 credit 依規則可省。

**後果**：批次跑到一半才收到「不准生圖」的要求時，已寫好的稿子無法驗證，只能整批重跑。
（該次浪費約 4 篇的額度。）

**解法**：把配圖政策**在批次開跑前就確定**。要事後查核的話，唯一可靠的訊號是封面有沒有 `coverImageCredit`。

### 坑四（順帶）：平行批次時模型會各自跑 build

`--write-only` 的 prompt 原本只寫「不要 git add / commit / push」，沒說不要 build。
實測 6 篇有 5 篇自己跑了 `pnpm build`，多個進程同時對同一個 `dist/` 讀寫，
產生「每次缺的檔案都不一樣」的 ENOENT 競態，白白耗時。

**解法**：prompt 明確禁止 `pnpm build` 與 `pnpm check:links`——那是外層批次驅動的事。

## 怎麼避免重犯

- **配圖政策屬於「開跑前要問清楚」的那一類**，不是可以邊跑邊調的參數。一旦跑了就無法回頭驗證。
- 要求模型「不要做某件事」時，如果那件事有副作用（花錢、產生無法辨識的產物），
  **一定要有機械層擋**，prompt 只是讓它一開始就走對路。
- 拿掉一個「安全網」時，先想**那張網原本在掩蓋什麼**。生圖掩蓋的是「圖庫找不到合適圖」與
  「同 query 回同一張」這兩件事，關掉它們就會浮上來。
- 平行批次的 prompt 要明確列出**所有不該做的全域動作**（git、build、check），
  因為單篇跑得好好的動作，在平行時會互相破壞。
